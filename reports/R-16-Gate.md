## 二、这一轮最值钱的一件事：删掉一个重复的渲染器

`pack` 和 `drill` 各自拼一套记忆文本，已经存在了三轮（M11 起）。它们的差异
只在细节：`pack` 用 `_day`（不带区间、不带问号），`drill` 用 `_fmt_time`（带）。

写 M16 时才发现，这意味着**同一条记忆在 CLI 和 prompt 里的时间可能不一样**：

```
CLI  ：[记忆 · 2026-11-04? · warm]      ← 带问号
prompt：[记忆 · 2026-11-04 · warm]       ← 不带
```

问号是 M8 特意打的"这个时间是猜的"标记。在 prompt 里丢掉它，模型就会把
猜测当成事实去算天数。这类 bug 不报错、不崩溃，只是让判断悄悄错一点。

现在 `format_event` 是唯一出口，`_day` 删了。`test_pack_block_equals_format_event`
逐字比对两边的输出——不是"看起来一样"，是 `==`。

## 三、三个数字，都是算出来的不是拍出来的

### 1. `estimate_tokens` 偏高 30%，内容预算要除掉

`estimate_tokens` 是给窗口预算用的（宁可高估）。直接拿它比 §5.3 的 90，
hot 档实际只用掉 2/3 额度。换算后三个样例是 65 / 65 / 19，正好落在区间中段。

**这件事的教训是"单位要对齐"**：同一个函数、同叫 token，一个带安全系数、
一个不带，混用不会报错，只会让所有阈值悄悄偏 30%。

### 2. 摘要让位原文，而不是原文让位摘要

warm 70 token，加了原文之后摘要只剩不到 10 token，裁出来是"用户下周从字…"。
半句摘要比没有更糟。所以有原文时，摘要额度不到 20 就直接不给。

### 3. pinned 的超额是设计的一部分

"hot 60~90，pinned 再加原文"——这两句本身就意味着 pinned 会超 90。
上限放到 130（90 + 一句引文 40），数量由 C 段的 200 token 提醒兜住。

## 四、事故 84 值得单独记：排除表太短，误伤自己的正例

```python
_FALSE_FRIENDS = ("记住密码了吗", "记住了吗", "我记住")   # 错
```

`"我记住"` 把 `"帮我记住，我妈生日是腊月初八"` 一起挡掉了。识别率 19/20，
漏的就是这条。

修法不是加更多 marker，是把排除项写完整（`"我记住了"` / `"我记住过"`）。
**只测正例的话这个 bug 永远抓不到**——12 条正例全过，只有那一条漏，
而 20 例的整体数字（19/20）又刚好卡在合格线上。

这和 M15 的教训是一对：
- M15：`frozen` 只在强判据里查（**漏了另一条路径**）
- M16：排除表子串太短（**反向条件写得不够精确**）

两个都是"条件写宽了/写窄了"，两个都不会报错。

## 五、真机库现状（M16 后的装配）

```
$ hippo recall 我搬家了记得吗 --dir /tmp/h2 --raw
总 token 943
  persona   171 / 500
  card      295 / 400
  pinned    192 / 200      ← 已接近满，M16.2 的提醒阈值就在这
  memory    237 / 600
  dynamic    32 / 150
  anchor     11 /  20
```

`pinned` 段 192/200 是 facts 渲染出来的（不是 pinned 事件），说明 C 段
预算在真实数据上**确实会撞到上限**。M16.2 的提醒只看 pinned 事件条数，
所以这里不会误报——但如果哪天 facts 也能把 C 段撑爆，得另做一条提醒。
这条留给 M17 之后处理。

## 六、给 M17 的交代

1. **`_fmt_time` 现在是三处共用**（D 段、CLI 预览、下钻原文）。M17 要做
   三重时间戳/时区，动它之前先跑 `test_m11_2_format.py` 和
   `test_m16_1_depth.py`——两边都在逐字比时间字符串。
2. **`2024-06-xx` 这种"未知日"的表达还没做**。现在是 `2024-06`，
   如果 M17 想显示成"2024 年 6 月（日期不详）"，改 `_fmt_time` 一处即可，
   但要注意它会让每条 cold 记忆多 3~5 token。
3. **相对时间（"三周前"）现在完全不出现**。M17 的三重时间戳如果要在注入里
   加相对时间，它会**每轮都变**，直接破坏 §5.1 的缓存前缀设计。
   建议只放在 E 段（动态段，本来就每轮变），不要进 D 段。
4. **垃圾实体仍未清**（27 个里 13 个是 `用户~6\x1f6` 残留）。M17 不碰实体，
   可以继续拖着；但 M18 的存疑池要按实体问"你说的是哪个老王"，
   到那时必须先清。
