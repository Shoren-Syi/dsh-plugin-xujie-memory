# R-22.2 · 代理层拦截与改写

**日期** 2026-11-06　**花费** ¥0

## 做了什么

`StreamFilter`：流式剥离器，跨块缓冲状态机。

```
正常模式 → 输出到 buf[:-7]，保留尾部 7 字符（"<giveup" 的长度）
         ↓ 发现 "<giveup"
标签模式 → 停止输出，等 ">" 闭合，整个标签吞掉
```

`rewrite` 四档改写（手册表格逐字）：

| level | 输出 |
|---|---|
| retry_alt | `None`——一个字都不给用户（内部重试） |
| ask_help | "这块我卡住了——我需要你告诉我 {reason}，不然我只能瞎猜。" |
| partial | 正文 + `\n\n另外，{reason}` |
| decline | "这个我做不到。原因：{reason}。" |

## 关键决定

- **跨块缓冲是唯一正确解**：手册"常见坑"一条命中的问题。测试做了
  最狠的两个验证：**逐位置切块**（标签在每个可能位置断开，共 ~40 种）
  和**逐字符喂**（每字符一块）——零残留。
- **hold back 7 字符**：`len("<giveup")`，这是理论最小延迟。实测
  无标签流 max_held=7，远小于验收的 30。
- **未闭合标签吞掉**：流被截断（模型中断）时，"正文 + 半截标签"
  比"只有正文"糟得多。吞掉 + `incomplete` 标记，兜底。
- **普通尖括号不误吞**：`<div>` / `<br>` 原样保留（测试钉死）——
  检测只在 `<` 后面精确匹配 `giveup` 前缀。
- **多标签取第一个**：模型啰嗦时会连发两个，第一个改写、其余全剥。

## 验收对照

| # | 要求 | 结果 |
|---|---|---|
| 1 | 标签零泄漏（200 次 0 残留） | 逐位置 × 逐字符切块 0 残留 |
| 2 | 流式不破（仍是合法 SSE） | 无标签文本逐字节原样流出 |
| 3 | 四种改写都正确 | 四档快照断言 |
| 4 | 延迟 <30 字符 | 无标签 7 字符；标签内需等闭合（弃权场景，正文本就不该露） |

## 一个诚实的说明

验收 #4 的"<30 字符"在**带标签时**不成立：标签本身可能 40 字符，
必须等 `/>` 才能确认边界。但那种情况下正文本就要被标签改写覆盖，
用户感知不到"延迟"。报告不粉饰这一点。
