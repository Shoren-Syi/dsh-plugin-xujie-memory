# R-23.1 · 动作登记

**日期** 2026-11-06　**花费** ¥0

## 做了什么

1. **`ledger.register()`**：写 `ledger(action_id, action, action_kind,
   predicted, ts, settled=0)`。四类自主动作：好奇探索 / 改文件 / 提议 / 发消息。
2. **`detect_kind()`**：关键词表 + 正则双通道。纯子串匹配会漏掉
   "我要改**一下**配置"这种中间插量词的短语，而它是最典型的改文件意图。
3. **`looks_requested()`**：用户明确要求做事 → 不登记（被动响应）。
4. **`clamp_predicted()`**：统一到 [-1, 1]。模型给 7 分 → 0.7；
   1.5 → 1.0（越界，不是"1.5 分"）；NaN/inf → 0。
5. **迁移 014**：`ledger` 加 `action_kind`、`settled_at` 两列 + 索引。

## 关键决定

- **加列不加串**（沿用 M22.3 的 giveup_level 模式）：动作类型是统计维度，
  塞进 `action` 文本里等于让每个查询做字符串解析。
- **十分制的下界设在 2**：`_clamp01` 的规则是" >1 就 ÷10"，套到账簿上
  会把 1.5 判成 0.15——方向对、量级错。要么是真越界（1.2），要么是
  十分制（7），没有"1.5 分"这种东西。
- **被动判定的门槛压得很低**：宁可多判被动（多一条空账，无害），
  也不能把服务记成自主（给本职工作记奖惩，会让 AI 之后不敢主动做事）。
  词表只收显式请求词（"帮我/请你/麻烦/改一下/生成/翻译"），不做意图推断。
- **`ts` 可由调用方传入**：回填历史对话时用对话时刻。3 天过期线按 `ts`
  算，用墙钟的话补录三个月前的对话会让所有历史动作"刚刚发生"，
  永远不会过期，然后被今天一句抱怨批量结算。
