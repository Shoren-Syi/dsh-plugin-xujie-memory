## 二、修掉的四件事

| # | 问题 | 严重度 | 表现 |
|---|---|---|---|
| 1 | `persist` 把模型给的 `type` 整列丢掉，写死 `"person"` | **高** | 朝阳/海淀 进了角色卡候选池，`CHECK` 约束全过 |
| 2 | `UNIQUE(session, canonical)` 不允许同名跨类型 | **高** | 一旦标错类型，**永久**改不回来 |
| 3 | 同一批抽取里 trait 复述 5 遍，confidence 被加到 0.95 | **高** | 一次抽取制造"极其确定"的假象 |
| 4 | aliases 收集用 `list.extend`，落库 8 个重复项 | 中 | 不影响功能，但卡上显示一长串"王哥 王哥 王哥" |

第 1 条是这次最有价值的发现。它从 M5 就存在，跑了 300 多个测试、
3 次真机评测都没暴露——因为**从来没有人查过 `entities.type`**。
约束合法、插入成功、统计正常，只是语义全错。

第 3 条是探针抓到的。`tools/probe_alias.py` 打印"模型每轮给的实体"，
我才看见同一条 trait 在 5 条事件上各挂了一次。如果只看最终库里的
"2 条 trait"，会以为一切正常——**数字对，成因错**。

## 三、地图一：0.8 阈值是死路径

手册写"trigram 相似度 > 0.8 就合并"。实测 **630 对实体，没有一对到 0.8**，
最高 0.25。

```
"老王" → {^老王, 老王$}
"老李" → {^老李, 老李$}      交集空 → 0.00
"王建国" → {^王建, 王建国, 建国$}
"王建军" → {^王建, 王建军, 建军$}    1/5 → 0.20
```

中文两字名补边界符后只有两个 gram，三字名差一字只剩 0.2。
这条规则**在中文人名上不可能触发**，等价于 `a == b` 的昂贵写法。

我没有删（英文名会触发），但它不构成防线。真正的合并来源是
**模型在 aliases 里显式声明**（prompt 规则 9）。

按这个结论，手册里"0.6~0.8 走 doubt"也不可能触发，所以改成
"同姓同长差一字 → doubt"。这是本轮第二处偏离手册。

## 四、地图二：合并不可逆，所以自动合并只有一条路

`resolve_entity` 从不把两个**已存在**的实体缝起来，只做"命中就返回"。
`merge_entities` 是独立入口，只给 `hippo merge` 和人工确认用。

原因是真合并要迁 4 处引用（traits / facts / event_entities / events.entities JSON），
任何一处漏了都会产生"挂在壳上的记忆"。测试 `test_merge_moves_traits_and_events`
逐项断言，`test_merge_frees_the_old_name` 锁住"合并后原名能重新创建"——
第一版没做这一步，`canonical` 原地留着，三个月后某次抽取会撞 UNIQUE。

顺带修了迁移器：006 重建 `entities` 时，`DROP TABLE` 在 `foreign_keys=ON` 下
顺着 CASCADE **静默清空了 `event_entities`**，而事后 `foreign_key_check`
返回空列表——级联删完恰好是"一致"的，只是数据没了。

现在的守卫是重建前后比对子表行数，少一行就回滚。
`test_rebuild_migration_keeps_child_rows` 是哨兵。

## 五、回答 M6 留下的问题：拆多细

M6 收工时记了一条待办："宁可多拆"和"成本要低"开始冲突，M7 必须定边界。

本轮实测：

| 口径 | 数值 |
|---|---|
| 单窗口成本 | ¥0.00188（14 窗口 ¥0.0263） |
| 单事件成本 | ¥0.00058（45 事件） |
| 事件/窗口 | 3.2（长文本窗口 5 条） |
| 成本结构 | 输出 token 占 97%（M5.5 结论，本轮未变） |

边界我定成两条，都能机械判定：

1. **一条事件至少包含 1 个可检索细节**（人 / 地 / 时间 / 数字 / 决定）。
   拆出来只剩"他说挺好的"这种，就不该独立成条。
2. **单窗口成本上限 ¥0.005**，是当前水位的 2.6 倍。
   超过说明拆得太碎，先看事件数：>8 条/窗口就要人工抽查。

第 2 条是个"止损线"而不是"目标值"。它的作用是在 M28 之前任何一次
prompt 改动后，能立刻发现"成本涨了 3 倍"。

## 八、下一步

M8 事实与矛盾。进 M8 之前有三件事已经就位：

1. `facts` 表有 `valid_from/valid_to`，`set_fact` 已实现"同值幂等 / 异值替换"，
   M8 只需要加 `key` 词表与"未知 key 降级"
2. 槽位机制可以复用到 facts（`key` 本身就是槽位）
3. 实体归一已能保证 fact 挂对人——这是 M8 的前提，
   否则"用户/职业"会挂到地名上

M8 的真正难点不是写入，是**判定"这两条是不是矛盾"**。
M7 用 slot 解决 trait，facts 天然有 key，问题会小一些。
但"值不同但等价"（"上海" vs "上海市"）会制造假矛盾，
需要一层值归一，这个手册没写。
