## 二、should_ask：六个 if，不是权重公式

手册 §8 的原则逐条翻译，**顺序也不动**（从最硬到最软）：

```python
if asked_this_turn: return False          # 一轮 1 条，DoD 硬约束
if d.confidence > 0.75: return False      # 基本懂了，问了像抬杠
if d.impact < 0.4: return False           # 问了也不影响理解
if d.cost > 0.7: return False             # 问出口的社交代价太高
if d.expires < now: return False          # 过期的不问（M18.3 会转记忆）
if turn - d.last_asked_turn < 8: return False   # 刚问过还问 = 复读机
if d.asked_count >= 2: return False       # 问两次没答案，第三次是骚扰
```

confidence 的语义在模块 docstring 里钉死：**"我已经理解了多少"，
越低越该问**。这是全模块最容易读反的地方。三个数是档位不是精度
测量，别拿它们做加权求和。

## 三、边界值都有主

- `confidence == 0.75` 可问（条件是 >）；`impact == 0.4` 可问（<）；
  `cost == 0.7` 可问（>）；冷却 `turn - last == 8` 放行（<）；
  `expires == now` 仍可问（<，到期当刻不算过期）。
  五个边界各有一条测试，改常量 = 改语义，测试守住。

## 四、pick 的选择标准与并列

impact / cost 最高（cost 下限 0.01 防除零）。并列时保持库序——
active_doubts 按 `impact DESC, id DESC` 排，意味着**并列时新条目
先出**。这是刻意的：老疑问已经等了很多轮，新触发的疑问与用户
当前话题的相关性更高。没有引入第二把尺子。

## 五、pack 接入

`_dynamic` 的存疑段从"取 impact 最高的第一条"（M13 占位版，会
复读机式追问）换成 `pick_doubt` + `format_doubt`。注入格式固定：

```
[存疑] 你不确定「X」。如果想问，问一次就好，问完不再纠结。
```

模板是常量，措辞一改行为就不可预测，测试逐字比对。

## 六、sim_throttle 的剧情（asks=3 怎么来的）

10 条疑问：3 条可问 + 7 条被拦（逐条对应六个拦截条件 + 过期）。
turn 1/2/3 各注入一条；turn 5/6/9 用户逐个回答（M18.3 的 resolved
闭环）；之后池内再无可问。`python -m hippo.tools.eval_doubts`
（DoD 评测，见 R-18-Gate）用 50 轮真实语感对话复验，asks=5，同样 ≤5。
