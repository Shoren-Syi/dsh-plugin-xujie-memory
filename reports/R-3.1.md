## 3. 三个必须记下来的问题

### 3.1 最后一轮丢失（最值钱的一个）

P0 冒烟第一次跑：`round 20/20 ok | turns=38 | metrics=19`。

客户端 20 轮全成功，服务端只记账 19 轮。

定位过程：
- 单元测试全绿 → 不是逻辑错
- 看服务端日志：第 20 轮的 `request.received` 有，`turn.written` 没有
- 说明请求进来了，但结账代码没执行

根因：结账写在生成器的 `finally` 里。客户端读到 `data: [DONE]` 就 `break` 并关闭连接，Starlette 随即取消生成器——**`finally` 可能根本不执行**（或者执行到一半被中断）。

修法：收到 `[DONE]` 的**当场**结账，`finally` 只做兜底，用 `settled` 标志保证幂等。

为什么单元测试测不出来：测试用 `aiter_text()` 把流读完才断言，生成器自然结束，`finally` 一定执行。**只有"读到 DONE 就断"的客户端才会触发**。已加 `test_last_turn_saved_when_client_quits_at_done`，且必须过真 TCP（`ASGITransport` 会读完整个流）。

### 3.2 delta 对齐用错了方向

第一版用「最长公共**后缀**」对齐 known 与请求 messages：

- known `[u0, a1]`，新请求 `[u0, a1, u2]`
- 后缀比对 `a1` vs `u2` → 永远不匹配
- 于是每轮都判定"全是新的"

看起来没错，因为最终只取最后一条 user——**但那是另一层兜底在救，这层算法根本没工作**。

改成「最长公共**前缀**」：客户端按顺序重发历史，known 应该是 msgs 的前缀。这样 `matched=2`，delta 只剩 `[u2]`。

### 3.3 兜底 session 对"每轮只发一条"的客户端会碎

`test_single_message_client` 一开始没传 session，结果两轮落到两个不同 session（`auto-d0d8…` / `auto-f757…`）。

原因：兜底是 `sha256(首条 user 消息)`。每轮只发当前一条时，"首条"就是当前这条，内容不同 → 哈希不同 → 每轮一个新会话。

这不是 M3 的 bug，是 M2.3 兜底策略的边界。带完整历史的客户端（SillyTavern / Chatbox）不受影响。已登记为遗留。

## 4. 性能

| 指标 | 值 | 说明 |
|---|---|---|
| 单轮写入（新建连接） | **4.5ms** | 页缓存冷启动，与库大小无关 |
| 单轮写入（常驻连接） | **0.072ms** | 快 62 倍 |
| 代理首字节（curl 实测） | **2.3ms** | 含转发 + 落库准备 |
| 代理首字节（httpx 实测） | 44ms | **客户端噪声**，见下 |

### 那 40ms 不是我们的

`smoke_p0` 报 `avg_ttft=41ms`，一度以为是 M3 把请求路径拖慢了。逐步排除：

| 假设 | 验证 | 结论 |
|---|---|---|
| 日志写盘慢 | `HIPPO_LOG=off` 重跑 | 仍是 41ms，否定 |
| 读 turns 慢 | 单测 `open+get_turns` | 0.38ms，否定 |
| 上游 send 慢 | monkeypatch `AsyncClient.send` 计时 | **3ms**，否定 |
| 服务端写 socket 慢 | `curl -w %{time_starttransfer}` | **2.3ms**，否定 |

结论：**httpx 在 keep-alive 连接上的第 2 个请求起，有 40ms 的延迟行为**（delayed ACK 类）。curl（每次新连接）和真实浏览器不会命中。

所以报告里 `avg_ttft` 这个数字要理解为"含 httpx 客户端噪声"，代理自身开销是 2.3ms。

## 5. 与手册的偏差

| 偏差 | 理由 |
|---|---|
| 只写「最后一条 user」，不写整个 delta | 客户端改写历史（重生成 / 编辑）时公共前缀会失配，delta 变成整段历史，全写进去就是几百条重复。只取一条，最坏是漏记一轮，不是污染全库 |
| 增加单条 64k 字符上限 | 手册没提。防的是"粘贴一整本小说"把库撑爆；触发时 `partial=1` 留痕 |
| 增加 `_is_duplicate` 去重 | 手册没提。客户端重试会原样重发，不去重就多记一轮 |
| 常驻写连接 | 手册没提。4.5ms 发生在客户端关连接之前，是实打实的体感；复用后 0.072ms |
