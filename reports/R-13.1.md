# R-13.1 预算表与裁剪

> 里程碑：M13.1（主干 ★）
> 日期：2026-11-05
> 产出：`hippo/core/pack.py`、`tools/bench_pack.py`
> 数据：`tests/test_m13_1_pack.py`（18 例）、99 轮真机库基准
> 结论：**达标**。平均 **886 token**、最大 **1092**、**0/99 超预算**、确定性 100%。

---

## 一、先解决一个矛盾：1100 和 1870

手册的分项预算加起来是 1870：

```
500(人设) + 400(角色卡) + 200(钉住) + 600(记忆) + 150(动态) + 20(锚) = 1870
```

DoD 却写"每轮上下文 ≤1100（不含对话）"。两者不可能同时成立。

**决策 D79：1100 是硬上限，分项数字是"这一段最多能占多少"。**

先按分项装，总超 1100 就从优先级最低的块开始砍：

```
D 记忆 → E 动态 → B 角色卡 → C 钉住 → A 人设 → 锚
```

依据是"没了它，这段对话还成不成立"：D 砍掉两条摘要，AI 少知道两件事；
A 砍掉，它就不是那个人了。锚永远不砍（11 token，砍了模型不知道今天几号）。

真机 99 轮的结果：

```
轮数 99   平均 886 token   最大 1092   超预算 0/99
```

最大 1092 离 1100 只差 8 个 token——说明预算**真的在起作用**，不是没撞到。

## 二、决策 D80：结果级复用

M12 量出"话题切换"触发率 45%。如果每轮都重新装 D 段（600 token），
缓存命中率会很难看。

但**重新检索 ≠ 内容变了**。所以这里比的是检索结果本身：

```
新一轮的 8 条 id 和上一轮的重合 ≥ 60% → 直接复用上一轮的 D 段字节
```

语义判断会猜错，id 不会。真机上 99 轮复用 **57%**。

复用必须是**逐字复用**，不能"重新渲染一遍"——重渲染哪怕内容一样，
只要有一条事件的顺序不同，字节就不同，缓存就断。

## 三、裁剪的证据：谁先被丢

| 场景 | 谁超了 | 谁被丢 |
|---|---|---|
| 40 条长记忆 | D（600） | D 尾部（低分的） |
| 30 个实体 × 4 条特征 | B（400） | B 里特征最少的那个"人" |
| 钉住 1 条 + 40 条长记忆 | 总预算 | D 先空，C 保住 |
| 人设文件本身 800 token | A（500） | 截断 + `pack.over_budget` 告警 |

`dropped` 列表每轮都记。不记的话"AI 怎么不记得了"永远查不出来——
用户问的是"你为什么忘了"，系统只能回答"我没忘"，因为没有证据。

## 四、两个上游数据问题，pack 只能兜住

**① 同一个 key 有多条 active 事实。** 真机库里有三条同时 active 的 `commute`
（飞机 / 步行 / 高铁）——那是三个人的通勤混在一个 key 上（M8 的遗留）。

原样倒进 prompt，模型会认为用户既坐飞机又步行。所以 C 段按 key 去重，
取 `valid_from` 最新的那条，等于"以最后一次说的为准"。

这是**降级**不是修复：真正的修法是 facts 带 entity_id 并在写入时消歧。
留给 M14。

**② 角色卡里"用户"也是实体。** 用户的 traits 和"老王"的 traits 平铺在一起，
B 段读起来像"老王：（我的推测）有点内向；用户：怕猫…"。可读性尚可，
但 B 段的排序是按特征数，人的特征最多，永远排第一。

## 五、确定性

同样的输入 100 次，字节必须一样。三条纪律：

1. **不拼 dict**。所有段落手写模板 + 固定顺序。`json.dumps(dict)`
   在 CPython 3.7+ 是插入序，但只要有人把某个值改成 `set` 就完了。
2. **浮点数不进 prompt**。分数、置信度是内部排序用的，写进去会因为
   `0.7000000001` 这种问题让字节变来变去。
3. **时间锚只到分钟**。带秒的话每分钟都变。

```
确定性 1/1（100 次 + 5 个新会话，digest 全一致）
```

第 2 条有测试守：`test_no_float_in_text` 断言 prompt 里不出现 `0.5` / `score`。

## 附：为什么 D 段几乎不会超预算

`_trim_to` 对 D 段的裁剪分支实际很少走到——因为 L2 已经按
`memory_budget_ratio=0.6` 装填过了（8 条 × 80 = 640 的上限里只用了 360）。

真正会超的是 B 段：人一多就顶。所以 `test_dropped_is_logged` 造的是
30 个实体 × 4 条特征，不是 40 条长记忆——**测试要造真的会超的那个方向**。
