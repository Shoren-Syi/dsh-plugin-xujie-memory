## 二、手册公式在这里是失效的，不是"阈值定高了"

手册给的是：

```
相似度 = 关键词 Jaccard × 0.6 + 摘要 trigram Jaccard × 0.4，阈值 0.75
```

在 142 条标注数据上，把**候选对内部**（同 session、30 天内、至少 1 个关键词
重合）的 30 个"应该合并"对和 10 个"禁止合并"对全部打分：

```
应合并 30 对：min 0.12   中位 0.30   max 1.00
禁止   10 对：max 0.20   中位 0.15
              ↑ 重叠区 [0.12, 0.20]
```

**分布是交错重叠的**：12/30 个应该合并的对，分数低于"禁止合并"里的最高分；
7/10 个禁止合并的对，分数高于"应该合并"里的最低分。

于是：

| 阈值 | 命中应合并 | 误报禁止 |
|---|---|---|
| 0.75（手册） | 6/30（**20%**） | 0 |
| 0.60 | 10/30（33%） | 0 |
| 0.50 | 10/30（33%） | 0 |
| 0.34（已经低到荒谬） | 12/30（**40%**） | 0 |

**它精确，但召回天花板是 40%，而且降阈值换来的召回极为有限。**
换句话说：这套公式能识别"几乎逐字重复"的那一小撮，识别不了"同一件事换个说法"——
而那才是重复陈述的绝大部分。

原因在 M12 的 D75 就量过一次，只是那时没往巩固上用：

> Jaccard 的分母是并集。重复陈述的典型形状是**第二遍更短**
> （"我不吃辣" 是 "真的，我一点辣都吃不了" 的复述）。
> 第一遍说得越详细，分母越大，分数越低。方向正好反了。

## 三、换成覆盖率，然后发现单用覆盖率会连锁

覆盖率把分母换成**较小一方**，这对"短的一方是长的一方的子集"这个形状是精确的：

```python
def _coverage(a, b):
    return len(a & b) / min(len(a), len(b))
```

在同样的 40 个候选对上：命中 **25/30（83%）**，但误报 **6/10**。

误报的形状高度一致——**两个各只有 2 个关键词、共享 1 个**：

```
{忌口, 冰饮}        vs {忌口, 吃不了辣}        → 0.5  ← 共享的是类目词
{朝阳, 居住}        vs {朝阳, 海淀, 搬家}      → 0.5
```

更严重的是**链式蔓延**。真机库里：

```
13 我住在朝阳                    {朝阳, 居住}
75 我从朝阳挪到海淀了            {朝阳, 海淀, 搬家}     ← 桥
92 我昨天下午搬家，从朝阳到海淀  {海淀, 搬家, 房租}
```

13 和 92 **一个关键词都不共享**，但因为都跟 75 过线，被并查集串成了同一个簇。
single-linkage 的经典病症：一条弱边就能把两个话题焊死。

所以判据拆成两层，而不是"取低阈值一次跑完"：

```
1. 强判据 cov_strict   → 自动合并（高置信，先定骨架）
2. 弱判据 kw_cov       → 只能往已有簇上挂，不能把两个簇连起来；记 strong=0，可 unmerge
```

分两步的关键不是阈值不同，是**拓扑权限不同**：强边可以连簇，弱边只能挂点。

## 四、`cov_strict`：为什么卡在"2 个词必须完全包含"

```python
if raw 逐字相同:            return 1.0
m = min(len(a.kw), len(b.kw))
if m < 2:                   return 0.0
if m == 2:                  return 1.0 if 共享 2 个 else 0.0
return 共享数 / m
```

`m == 2` 那一支是整段代码里唯一"不讲道理"的地方，必须解释清楚：

抽取器只给 2 个关键词时，"共享 1 个"算出来就是 0.5，**而 0.5 会过任何合理阈值**。
也就是说在这个样本量下，"共享 1 个词"这个事件本身不携带信息——它必然发生。

实测的 5 个误合并全是这个形状，共享的那个词往往是"吵""加班""忌口"这类泛词。

代价明确：真重复里也有 2 词共享 1 个的

```
"北大人民医院复查"  vs  "医院复查"     同一件事，该合，会被这一支挡掉
```

它们落进弱判据那一档（仍然合并，只是标记成可撤销），不是丢掉。
**这就是"宁可漏合，不可错合"的具体落点。**

## 五、时间窗：手册 7 天只够跑出 31%

手册写"时间差 < 7 天"。实测这条会切断将近一半的话题：

```
16 个话题里 7 个（44%）的跨度超过 7 天，最长 28.2 天
相邻两次提及的间隔：中位 4.0 天，p90 12.1 天，27% 超过 7 天
```

按不同窗宽跑同一份数据：

| 时间窗 | 簇数 | 合并条数 | 话题内已合并对 | 跨话题簇 |
|---|---|---|---|---|
| 7 天（手册） | 8 | 12 | 16/51 = **31%** | 0 |
| 15 天 | 13 | 21 | 25/51 = 49% | 2 |
| **30 天** | 14 | 23 | 27/51 = **53%** | 2 |
| 60 天 | 14 | 23 | 27/51 = 53% | 2 |

两条结论：

1. 7 天窗只能拿到 31%，因为"我不吃辣"这种事会跨整月反复讲。
2. **30 天之后完全饱和**，60 天一个簇都不多。跨话题误合从 15 天起就是 2，不随窗宽增长。

所以取 30 天：它是饱和点，不是"越大越好"的中间值。窗口越大候选对越多的
担心在这份数据上不成立——候选对由"至少 1 个关键词重合"控制，不由窗宽控制。

## 六、造数据踩的三个坑（这部分比算法更值得记）

判据是拿数据调出来的，所以**数据的坑会直接变成算法的坑**。三个都真实发生过：

### 坑一：filler 循环复用

```python
FILLERS[i % len(FILLERS)]     # 100 条 filler 灌 142 条事件
```

"地铁今天特别挤"被写了 6 遍，标注里它们是**不同事件**（`truth=None`）。
探针于是报"误合 55/57"——看起来算法烂透了，实际是数据在说谎。

修：手写 100 条互不相同的 filler。

### 坑二：关键词用字符切片

```python
"keywords": [what[:2], what[:3]]      # "吃了" "了碗"
```

得到一堆非词。这些假 token 之间又互相重合，造出 112 个候选对里 97 个是假的。

修：每条 filler 手写真实关键词。**关键词的质量决定了判据的上限**，
这一条在 M16 还会再疼一次。

### 坑三：`residual` 公式写反了

```python
residual = 条数 - 簇数          # 错
residual = 簇数 - 1             # 对
```

"多余重复"的定义是"每个簇里除了代表那一份，还剩几份"，是 `簇数 - 1` 的求和。
写成 `条数 - 簇数` 之后，指标变成"合并得越多越好"，而且**阈值越高读数越好**——
我差点顺着这个假象把阈值调高。

教训：指标写错的时候，它不会报错，它会给你一个自洽的、方向相反的结论。

## 七、指标本身也错过一次：pairwise 召回率是错的

第一版用 pairwise 召回率：

```
recall = 已经被合并进来的正例对 / 所有正例对
```

这个指标假设"同一话题的任意两条都该被直接判定为重复"。但聚类用的是并查集，
**只要链式连通就够了**：

```
A—B 是强边，B—C 是强边，那么 A 和 C 必然同簇，即使 cov_strict(A, C) = 0
```

于是这个指标会永远显示"召回不足"，然后诱导你去降阈值——而真正该做的是
让它链式连通。手册预期结果里写的 `clusters=214 pairs_scored=3120` 也是这个思路的残留。

修：改成**按簇算**的完整性/纯度，外加一个"话题内已合并对"作为参考（不设门槛）。
现在报告里那三个数（剩重复率、纯度、跨合）都是簇级的，和 DoD 的口径一致。

## 八、一个必须承认的天花板

词面方法分不开形状完全一样的两种对：

```
"北大人民医院复查"  vs  "医院复查"      同一件事，该合
"微信群里吵起来"    vs  "搬工位吵一下"   两件事，不该合

两条都是 2 个关键词、共享 1 个、覆盖率都是 0.5。
```

试过并且失败的信号：字符合集余弦、原文 bigram 重合、IDF 加权、按 df 门控
（**df 门控是负收益**：真证据恰恰是高频词——"搬家"df=3、"海淀"df=4 都是真合并的
依据，而误合并那条共享的"忌口"df=2，比它们都"稀有"）。

所以策略定死：**宁可漏合，不可错合**。漏合是效率问题（多占一个 prompt 名额），
错合是不可逆的信息损坏（原文还在，但检索层再也看不见那条独立记忆）。

这条策略的代价在 Gate 报告里量化成一条曲线（`CHAR_THR`），结论是**没有一档能把
两个 DoD 同时压住**，默认关闭。
