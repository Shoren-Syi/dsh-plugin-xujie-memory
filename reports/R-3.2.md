## 2. 一个写错过的切点

第一版在"第 5 条 user 刚进来"时切：

```
u0 a1 | u2 a3 | u4 a5 | u6 a7 | u8   ← 窗口在这里结束
                                    a9 被甩到下一个窗口
```

后果是抽取器看到"用户说了话，没人回"，关系全断，还容易把下一轮的内容错配到上一轮。

改成**只在 user 边界切**，且判断放在"下一轮 user 进来时"：

```
遇到新 user → 若上一窗已满 5 轮或超 token → 收尾上一窗 → 再把它放进新窗
```

代价：单轮超长时窗口会超 `max_tokens` 一点。收益：每一窗都是完整对话。这个交换值得——半轮对话对抽取器没有意义。

## 3. token 估算

```
cjk × 1.5 + other / 4，再 × 1.3 安全系数
```

实测：

| 文本 | 字数 | 估算 |
|---|---|---|
| 早 | 1 | 2 |
| 今天天气不错，我们出去走走吧 | 14 | 26 |
| hello world this is a test | 26 | 9 |

刻意偏高：低估的后果是撞 400（整轮失败），高估的后果只是窗口小一点（多一次调用）。不对称，所以往高估偏。
