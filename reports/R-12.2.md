# R-12.2 强制触发条件

> 里程碑：M12.2
> 日期：2026-11-05
> 产出：`core/topic.py`（`should_retrieve` / `new_entity_hint` / 节流）
> 数据：`tests/test_m12_2_trigger.py`（16 例）
> 结论：**达标**。新实体 100% 触发、回忆词 100% 深检索、四种 reason 都能出现。

---

## 一、判定顺序是成本顺序，不是概率顺序

```
recall      命中回忆词     → 一定要，而且连 L3
new_entity  出现新名字     → 一定要（不认识的人，不查就是装不认识）
cold_start  没有上一轮     → 一定要
same_entity 提到同一个人   → 一定不要（词会换，人不会）
switch      coverage 低    → 可能要
```

前三条的判断代价都是微秒级（子串匹配 / 一次正则），`coverage` 要查库。
把贵的放最后，是这一层能在 0.05ms 跑完的原因。

## 二、回忆词与细节词是两套，不要合并

| | 触发什么 | 例子 |
|---|---|---|
| 回忆词（M12） | 检索 + **连 L3** | "你还记得我上次说的那个事吗" |
| 细节词（M11） | 只触发下钻 | "当时怎么说的" |

"你还记得我上次说的那个事吗"要的是**想起来**，不是原话；
"当时怎么说的"要的是原话，前提是已经检索到了。

合并成一套的后果：要么每句"记得吗"都拉原文（贵），要么"当时怎么说的"
永远拉不到原文（因为"当时"不是回忆词）。

`tr.deep=True` 只有 recall 会给。M13 拿到它就直接调 `drill`。

## 三、新实体识别：只认两种句法位置

**这是启发式，不是 NER。** 只认：

```
称谓 + 名字      "我朋友老张" "我老板叫李总"
叫 + 名字        "有个人叫周深"
```

别的位置一律不猜。猜错代价是"多检索一次"（0.4ms + 可能 600 token），
但猜多了会把每句话都判成新实体，整套闸门就失效了。

实现上踩了两个坑：

**坑 1：正则贪婪。** `(?:朋友)([\u4e00-\u9fa5]{2,3})` 对
"我朋友老张下周结婚" 切出 `老张下`（3 字优先）。
修法：尾部常见字（上下说来了去要会能的了…）往回退，退到 2 字。

**坑 2：动词冒充名字。** "我朋友说好要来" 会切出 `说好`。
修法：候选首字不能在 `_BAD_HEAD`（说讲是的了在要会能…）里。

```
new_entity_hint("我朋友老张下周结婚")  → ["老张"]
new_entity_hint("我朋友说好要来")      → []
new_entity_hint("我朋友都是这样")      → []
```

已登记实体的名字/别名不算新——否则 "我朋友老王来了" 每轮都触发。

## 四、决策 D77：同实体必延续

```
上一轮提到老王，这一轮也提到老王 → 铁定在聊同一件事
```

这是最可靠的信号：**词会换（"搬家"→"通勤"），人不会。**

实现靠 `session_state.last_pack_entities`（M13 装配完回填）。
命中就返回 `continue`，不再看词面。

这条直接消掉了两类误触发："老王不是让你帮他喂猫"（陈述）、
"你老王家在哪"（问句）——它们词面上和上一轮毫无关系，但都在说老王。

## 五、决策 D78：节流默认关闭（实测有害）

加了 `min_interval_turns`：距上次检索不足 N 轮时，弱信号降级为 `throttled`。
理论上很合理——刚检索过，600 token 还在上下文里。

实测（99 轮）：

| 间隔 | 触发率 | 漏触发 | 误触发 |
|---|---|---|---|
| 0（关） | **45%** | **13%** | 26% |
| 1 轮 | 28% | **55%** | 21% |
| 2 轮 | 20% | 65% | 13% |

**它挡掉的大部分是真换了话题。** 触发率降了 17 个点，漏触发涨了 42 个点。
用"AI 忘事"换"省一点 CPU"，这笔账不划算——检索本身只要 0.4ms、0 token。

开关留着（有人的场景可能更在意成本），默认 0。
