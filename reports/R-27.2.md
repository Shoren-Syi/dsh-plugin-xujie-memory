## 一、口径：三个数，缺一个就是假账

```
cost = (P - C) × miss价 + C × hit价 + O × out价
       P 输入 token（pack 之后的整段上下文）
       C 其中命中前缀缓存的部分
       O 输出 token
```

`P` 取自 **M26 的 200 轮实测**（`eval_all --json` 的 `hippo.tok_per_turn`），
不是拿手册的 1100 估的；`O` 取本机真实 `metrics`（49 轮）的均值；
价格来自配置，不改代码。

**为什么不直接对 `metrics.cost` 求和**：那列只覆盖对话请求，抽取是后台任务，
成本只落在 `extract_runs`；而且它只回答"过去花了多少"，回答不了
"一天聊 100 轮要多少"。所以用同一套公式重算，顺便校验两边的差。

## 二、三档表

输出按 **150 token/轮**（普通聊天的一句半到两句）估。实测输出只有 40，
是因为本机那 49 轮是短回复测试流量，拿它当"正常聊天"会低估一半以上。

| 档位 | 轮/天 | 月 token | 月成本 |
|---|---:|---:|---:|
| 轻度 | 20 | 434,040 | **¥1.08** |
| 中度 | 100 | 2,170,200 | **¥5.41** |
| 重度 | 500 | 10,851,000 | **¥27.04** |

同一张表按实测输出 40 算，是 ¥0.55 / ¥2.77 / ¥13.84。
两个数都真实，差别只在"你聊得多长"——所以报告里给区间，不给单点。

**不含客户端自己的对话历史。** 装不装插件都要发的那部分（最近 5~20 轮）
不该记在插件账上。M26 的 `none` 基线 549 token 也是这个口径。

## 三、缓存：省 54%，不是 63%

手册示例写 `cache_hit=0.72 saved=63%`。按 DeepSeek 价目（miss ¥2 / hit ¥0.5）
算，72% 命中对应的节省是：

```
单价 = 0.28×2.0 + 0.72×0.5 = 0.92 元/M
节省 = 1 - 0.92/2.0 = 54%
```

63% 对应的是命中 84%。**手册那个数不是算错，是命中率假设不同**，
这里按 72% 如实报 54%，并给敏感性表（中度 100 轮/天）：

| 缓存命中 | 月成本 |
|---:|---:|
| 0% | ¥7.27 |
| 50% | ¥5.98 |
| 72% | **¥5.41** |
| 95% | ¥4.81 |

为什么默认 72% 而不是本机实测的 13.9%：本环境的上游是 mimo，
**不做前缀累积缓存**（R-13.3 三次对照证明）。13.9% 只是"系统提示固定"
带来的偶然命中，不代表 pack 的效果。我们这一侧的结构上限是 95%
（R-13.3 离线），DeepSeek 官方典型在 70% 以上。谁的上游命中多少，
自己对敏感性表。

## 四、和 M26 的一致性

| 项 | M26（R-26-final） | 本轮 | 差 |
|---|---:|---:|---:|
| hippo tok/轮 | 576 | 573 | -0.5% |
| 相对 none | 1.05x | 1.05x | 0 |
| 相对 full | 0.131 | 0.130 | -0.8% |

573 比 576 少 3 token，是 M27.1 的后缀兜底改变了检索结果（P23 命中后
D 段少装了一条更长的旧摘要）。**不是口径变了**。

账单校验（用记账时的同一份价目表重跑）：

```
重算 ¥0.0127  vs  记账 ¥0.0127   偏差 0.00%
```

换成 DeepSeek 价目表去重算历史账单，偏差 166.88%——那是**价格差**，
不是公式错。工具里对 >5% 的偏差会自动打一行说明，避免下一个人
把它当 bug 查一天。

## 五、抽取这笔钱

`metrics` 里没有抽取，单列 `extract_runs`。本机 49 轮里有 1 次抽取，
摊到每轮 ¥0.00008，占对话成本的 9%。重度用户每 5 轮一次窗口抽取，
按 `window_tokens=1200` 估是每轮 ¥0.0011——**和对话本身同量级**。
只算对话不算抽取，等于把账单砍一半。

## 已知偏差

1. 150 token 输出是假设，不是实测（本机没有长回复样本）。给了 40 的对照。
2. `P=573` 不含客户端历史，也不含工具调用/函数 schema；接了工具的客户端会更贵。
3. 缓存命中 72% 是上游行为，不受我们控制；只能保证前缀稳定（95%）。
