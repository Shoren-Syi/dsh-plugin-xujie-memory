# R-34 · DSH 会话和关闭时序（进行中）

2026-11-06。DSH 0.2.1-rc.5 独立 headless profile、独立 SQLite、用户提供的测试 API 账户；测试对话内容为虚构数据。

## 问题与修复

1. `assistant/message` 的正文在 `data.message.content`；现在支持该格式，并过滤 thinking 和 tool 块。
2. DSH 先组装提示词，后写入用户消息。旧代码从 `user/message` 才开始检索，因而可能晚一轮，重启后首轮缓存为空。现在收件箱事件触发检索，提示词 waterfall 有界等待检索结果，并保留 `pack()` 为唯一记忆文本来源；关闭提示词模板插值以保留记忆原文。
3. headless 退出时立即杀死内核可能丢掉在途消息及抽取。插件退出前等待写入队列并给后台任务最多 30 秒完成；仍未完成的内容留在数据库待后续处理。不同会话在抽取期间到来的新内容会被记入队列，不再被直接忽略。

## 验证

- 向隔离测试库加入一条先前未出现在 DSH 会话中的虚构暗号；重启 headless 并询问后，检查实际持久化的 `system/message` 包含暗号，模型最终回答也包含暗号。
- 修复前几次短会话后库里仅有 5 条用户消息和 3 条助手消息、0 次抽取；修复后再运行一次，记录变为 6 条用户消息、4 条助手消息、2 次成功抽取。旧运行已丢失的助手内容没有伪造补回。
- 添加真实内核冷启动提示词集成测试，以及受控的多个会话排队和收尾测试；Node 相关测试 10 项通过。
- README 已说明数据边界：数据库保存在本地，但模型抽取会向所配置服务发送对话片段，召回记忆会发给对话模型。
