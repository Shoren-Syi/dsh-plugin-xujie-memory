# R-41 · 检索调参无效，瓶颈在抽取密度

## 实验

同一批人工标注 20 题（真实会话），换四组检索权重：

| 配置 | 严格命中 |
| --- | --- |
| baseline（kw .55 / weight .25 / recency .10） | 5/20 |
| recency +.15 | 5/20 |
| kw -.15 / recency +.20 | 5/20 |
| soft_since +.15 | 5/20 |

**四组完全一样。** 说明漏题不是"排序把对的挤下去了"——调权重没有意义。

## 直接查具体题

```
Q: 用户要求生图的比例是多少？  （答案 3:4，库里摘要含它）
  trigger: fact_query   kws=[生图, 用户, 要求]
  L1 候选: 0            ← 候选生成是空的
  L2 取回: 0 (no_keyword_hit)
```

再看这些真实会话本身：`private-eval-*` 每个会话抽完只有 **2~5 条事件**。
换句话说——**检索层能挑的东西本来就很少**。以前所有"检索没选中"的漏题，
在这个体量下几乎是必然的：候选池只有 2~5 条，其中不含答案，那就一定漏。

## 结论

1. 检索调参（权重/软下限）在前述数据上**没有可测收益**，不做。
2. 真正的瓶颈是**抽取密度**：真实任务型对话里，每个会话只沉淀 2~5 条记忆，
   而人想问的事往往在没被抽出来的那些轮次里。
3. 下一阶段该做的是"**会话级摘要记忆**"：不是每 5 轮抽事件，而是会话结束时
   生成一条"这个会话在做什么、结论是什么"的记忆。这样即使单条事件稀疏，
   会话级记忆也能把上下文捞回来。
