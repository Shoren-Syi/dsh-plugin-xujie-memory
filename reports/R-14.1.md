## 一、先量，再抄

手册给的公式抄下来十分钟。但 `probe_weight.py` 在真机库（44 条事件、
90 天推进、每天两个话题被检索命中）上跑出来是四个红：

```
===== 手册公式 · 90 天 =====
hot 占比：day1 13.6% → day90 45.5%   区间 [13.6%, 52.3%]     （要求 5~15%）
clamp 削平率 16.3%      单调违例 1051 次      空闲期翻层 2134 次
初始 hot [11,12,13] → 90 天后 top-8 里只剩 1 条（DoD 要求 30 天内的都在）
最终 top-8：w=1.000 / 1.000 / 1.000 / 1.000 / 1.000 / 1.000 / 0.966 / 0.966
```

三条最刺眼的事实：

1. **权重自己在涨**，而且是**没被召回的那些**在涨（1051 次单调违例）。
   一条"越放越重要"的记忆，等于没有衰减。
2. top-8 里 6 条并列 1.000。**排序彻底失效**——下一步"按权重取前 8"
   变成"随便取 8 条"。而 L2 的 `w_weight=0.25` 就靠这个数。
3. 44 条事件**全部**在 hot/warm 之间翻层，最多的 90 天翻了 69 次。

## 二、四个病根与四处修正

### 病根 1：自指

`hl = HALF_LIFE[e.tier]`，而 `tier` 由 `weight` 算出来。追一遍就看见了：

```
day0  tier=1(hot)   hl=3    w=0.75
day1  tier=1        decay=0.79  w=0.72  还 hot
day2  tier=1        decay=0.63  w=0.57  掉成 warm
day3  tier=2(warm)  hl=30   ← 半衰期变了！用**绝对年龄**重算
                    decay=0.93  w=0.85  → 又回 hot
day4  tier=1        decay=0.40  w=0.36  → 又掉
```

不是"衰减"，是"在阈值上弹跳"。**修法不是调参，是断边**：
`hl` 改由 `w0` 决定，`w0` 是写入时定死的常量，永不自我引用。

测试 `test_tier_is_output_not_input` 钉死这条：同一条事件把 `tier` 从 1
改成 3，权重必须一模一样。

### 病根 2：半衰期的方向反了

手册 `hot=3 / warm=30 / cold=180`，读起来是"工作记忆忘得快"。
但 hot 是由"重要"判出来的。**重要的事忘得最快**——这不是记忆，是内存回收。

人的记忆反着来：吵架、告白、坏消息二十年都记得；午饭吃了什么晚上就忘。

所以按 `w0` 分档，越重要忘得越慢：

| w0 | 半衰期 | 覆盖的真机库事件 |
|---|---|---|
| ≥ 0.70 | 180 天 | 吵架那三条、辞职犹豫 |
| ≥ 0.40 | 30 天 | 绝大多数（搬家、工作、忌口） |
| < 0.40 | 3 天 | 目前没有（w0 下限是 0.40） |

第三档现在用不到，留着是为了以后 `_arousal_tier` 改了不至于悄悄退化——
`test_half_life_bands_are_configurable` 保证它还能被配置起来。

### 病根 3：arousal 收了两遍钱

`w0 = 0.40 + 0.50 × arousal`（写入时），公式里又 `× (1 + 0.3 × arousal)`。
同一份情绪计两次。后果是高唤醒事件一起手就顶到 1.0，然后被 clamp 削平
几十天——这期间"时间越久越低"在**输出上**不成立（曲线是平顶），tier 也跟着冻结。

去掉 arousal 因子。它在 `w0` 里，够了。

### 病根 4：用进废退的加成会顶棚

手册 `× (1 + 0.2 × min(rc,5))`。召回 5 次 ×2.0，再乘 arousal 1.3、
pin 2.0，最大 5.2 倍。`w0=0.75` 的事件 → 3.9，clamp 到 1.0。

而且 `last_access` 刷新**已经**把 decay 重置回 1 了，再加一次是双重奖励。

改成**延长半衰期**：

```
hl_eff = hl × (1 + 0.25 × min(rc, 5))      # 召回 5 次 → ×2.25
w = w0 × 0.5^(age / hl_eff)                 # 恒 ≤ w0 ≤ 1，永不需要 clamp
```

语义也更对："用得多 → 忘得慢"是**持久的性质改变**，不是一次性的分数加成。
`test_recall_never_pushes_weight_above_w0` 守这条。

### 顺带：pinned 的语义

手册 `pin = 2.0` 会让 0.5 的事件跳成 1.0，然后照样衰减——两个月后又冷掉，
只是过程好看一点。钉住应该是"**永不遗忘**"，所以给极大半衰期（36500 天）。
撤销钉住把 `pinned` 置 0，权重从那一刻按正常曲线重算。

## 三、修正后重跑同一份仿真

```
===== 修正版 · 90 天 =====
hot 占比：day1 6.8% → day90 6.8%   区间 [6.8%, 6.8%]
clamp 削平率 0.0%      单调违例 0 次      空闲期翻层 16 次
初始 hot [11,12,13] → 90 天后 top-8 里还剩 3 条
最终 top-8：0.731 / 0.700 / 0.650 / 0.600 / 0.550 / 0.539 / 0.533 / 0.533
```

| 指标 | 手册公式 | 修正版 | 要求 |
|---|---|---|---|
| 单调违例（权重自己在涨） | 1051 | **0** | 0 |
| clamp 削平率 | 16.3% | **0.0%** | — |
| 空闲期翻层 | 2134 | **16** | 越少越好 |
| hot 占比 day90 | 45.5% | **6.8%** | 5~15% |
| DoD：重要事件仍在 top-8 | 1/3 | **3/3** | 3/3 |
| top-8 是否可区分 | 6 条并列 1.000 | 0.731→0.533 | 必须可区分 |

## 四、阈值滞回

阈值 0.70 上有一条事件 `w0` 正好是 0.70（真机库 id=12）。没有滞回时它
每天翻一次层——90 天 30 次。tier 一抖，M16 的注入深度跟着抖：
同一条记忆今天给全文、明天给一行、后天又给全文。

加 0.05 的滞回带：升 hot 要 ≥0.70，掉出 hot 要 <0.65；出 cold 要 ≥0.35。

**两个边界的方向是相反的**，这一点我第一版写反了（`warm - hyst` 写成
`warm - hyst` 给 prev==3），结果"cold 更容易出、hot 更容易掉"，
比不用滞回还飘。测试 `test_tier_hysteresis_on_cold_edge` 抓到的。

修完空闲期翻层从 136 降到 16。

## 六、留给 M15 的话

1. **w0 的分布太窄**（0.40–0.90，实际集中在 0.45–0.65）。第三档半衰期
   （w0<0.40 → 3 天）永远用不到。要么调 `_arousal_tier`，要么承认
   "所有事都值得记 30 天"，两者选一个
2. `recall_cap=5` 是按"半衰期 ×2.25"定的。如果 M15 合并后单条记忆代表
   更多事件，这个 cap 可能要放宽
3. `_recency`（排序用，按 `event_time`）和 `compute_weight`（衰减用，
   按 `last_access`）是**两个不同的时间基准**，别合并。合并的后果：
   讲一件 2019 年的旧事，一进来就被判成极旧而沉底
