## 二、为什么用规则不用模型

判"这句话是不是在要求记住"很适合交给模型——但**这是每条 user 消息都要走的路**。
为它加一次 API 调用，等于把约束⑤（成本必须低）当场推翻，而且换来的是
一个本来就能做到 100% 的判断。

规则能做到，是因为中文里"要求记住"是**祈使句**，而祈使句有稳定形态：

```
记住 / 记一下 / 记下来 / 存一下 / 别忘了 / 不要忘了 / 一定要记得 / 必须记住
```

真正会误判的是陈述句和疑问句——`我记得你说过`、`你还记得吗`——
这两类都**不含**"记住"二字（差一个字：记得 ≠ 记住）。所以 marker 表里
绝不能放裸的"记得"。

`test_markers_do_not_contain_bare_jide` 就是钉这一条。

## 三、否定必须先判

```python
if any(n in t for n in _NEG):          return False   # 先否定
if any(f in t for f in _FALSE_FRIENDS): return False
return any(m in t for m in PIN_MARKERS)              # 后肯定
```

「不用记住这个，随口一说」含"记住"。顺序反了它会被钉住。

**这和 M15 那个 `frozen` bug 是同一种错法**：只查了正向条件，忘了反向条件
藏在另一条路径里。M15 那次是把"更正"合进了簇，这次差点是把"随口一说"
钉成永久记忆——后者的代价更持久，因为钉住是永不衰减的。

## 四、事故 84｜排除表写得太短，误伤了它自己的反例

第一版排除项写的是：

```python
_FALSE_FRIENDS = ("记住密码了吗", "记住了吗", "我记住")
```

识别率 19/20，漏的那条是：

```
"帮我记住，我妈生日是腊月初八"
        ↑ "我记住" 子串命中 → 被判成"应答"，不是"要求"
```

**排除表里的条目太短，会误伤它自己的正例。** 改成带收尾的完整说法：

```python
_FALSE_FRIENDS = ("记住密码了吗", "记住了吗", "我记住了", "我记住过", "记住过")
```

修完 20/20。`test_false_friend_list_is_not_too_short` 把这三句一起钉住——
只测正例的话，这个 bug 永远不会被抓到（正例全过，只有那一条漏）。

## 五、钉住必须立刻生效，不能等夜里

```python
if pin:
    tier = 1
```

不这样做的话，一条被明确要求记住的事要等到夜里 `recompute` 才变 hot。
中间这段时间它可能**根本没进过 prompt**——而用户明天就会问"你怎么忘了"。

权重不用在这里算：`set_pinned` 只改 `tier`，`weight` 保持写入时的 `w0`。
衰减由 M14 的公式管，钉住的半衰期是 36500 天（100 年），90 天后保留 99.83%：

| 天数 | 钉住 | 未钉住（w0=0.5） |
|---|---|---|
| 1 | 100.00% | 97.72% |
| 30 | 99.94% | 50.00% |
| 90 | **99.83%** | 12.50% |
| 365 | 99.31% | — |
| 3650 | 93.30% | — |

## 六、撤销不改 tier

```python
def set_pinned(self, event_id, pinned=True):
    if pinned:  UPDATE events SET pinned=1, tier=1
    else:       UPDATE events SET pinned=0
```

撤销时不动 `tier`。理由：撤销之后它该是什么档，由**权重公式**说了算，
手改等于替公式做决定；而且改错方向（该冷的不冷）比不改更糟。
下一次 `recompute` 会按当时的权重把它归位。

## 七、"一次提醒"的判据是条数，不是布尔

```python
def pin_warn_once(self, session, n, tokens):
    last = 上次提醒时的条数
    if n > last: 记下 n，返回 True
    return False
```

用布尔的话：用户清到 8 条之后又攒回 15 条，是**新的一次失控**，却再也不提。
用"条数涨了才提"：既不会重复（每轮提一次会让提醒变成噪声），也不会
漏掉第二次失控。

触发条件两个都要满足：

```
条数 ≥ 5（PIN_WARN_MIN）且 C 段 token > 200（pinned_tokens 预算）
```

按 token 而不是条数判"贵不贵"：3 条 200 字的钉住和 12 条短句一样占地方。

提醒文案带下一步动作：

> 你钉了 12 条记忆，C 段已经 260 token（预算 200），要不要清理几条？
> 用 `hippo pin --list` 看，`hippo pin --event N --off` 撤销。

## 八、`hippo pin`

```
$ hippo pin --event 2
已钉住 #2：近多了，走路二十分钟。对了老王说他下周要去深圳出差，让我帮他喂猫
它现在会以 hot 档注入（关键词 + 摘要 + 原文）。

$ hippo pin --list
钉住 1 条（永不衰减，每轮都进 C 段）：
  #2    近多了，走路二十分钟。…
合计约 154 token（C 段预算 200），超了会被裁。
```

手动入口有两个用处：自动识别只认祈使句（"这件事你千万别忘了"命中，
"我刚才说的都挺重要的"不命中）；以及误判时的修正手段。
