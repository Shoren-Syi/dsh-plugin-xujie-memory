# R-39 · 纠错分工：插件能做的自己做，剩下的让模型"无感"地反思

## 主人给的原则（2026-11-06 深夜）

1. 能用插件解决的，插件解决掉，别甩给模型；
2. 解决不掉的，让模型自己反思（人也会反思自己）；
3. 次数不能多——多了 token 花不住；
4. **绝对无感**：用户不该感到任何额外东西（提示、延迟、话术变化）。

## 被否掉的方案（记录在此，防止以后又有人提）

**往系统提示里加一行"若记忆有误请用 [纠正] 说明"。** 看起来最省事，但它是有感的：
- 多付 token（每轮约 20，看似小，按 20 轮/天 × 1 年算不是小数）；
- 会改变模型行为（开始主动纠正、开始写"我注意到我的记忆有误"），用户能看出来；
- 属于"把插件该干的活甩给模型"，正好违反第 1 条。

配置项 `reflect.correction_hint` 保留但**默认 False**，只在实验分支里用。

## 采用的设计：被动纠正挖掘（零提示词、零额外请求、零延迟）

不新增任何 LLM 调用，也不改提示词，只在**已有的消息流**里做本地解析：

1. **信号来源（双向）**
   - 用户侧：`不对，是十四号不是十五号` / `我记错了` / `改成周三` / `不是老王，是老李`
   - 模型侧：`更正一下` / `我上一条说错了` / `重新确认：…`（这就是"模型自己反思"，
     不需要它被要求，它本来就会在发现矛盾时这么说）
2. **只在能解析出"旧值 → 新值"时应用**：纯情绪化的"不对"（"不对，我觉得不行"）不算纠正。
3. **静默更新**：按已有的事实冲突逻辑（`facts.decide_fact`）supersede 或改写事件摘要，
   不产生任何面向用户的额外内容。
4. **限量**：`reflect.max_passive_per_day = 3`，超了当天不再应用（防止把闲聊里的"不对"
   全当纠正，也防止成本被这类解析拖高——虽然解析本身不花钱，但改错记忆的代价高）。
5. **无感指标**：不改首字延迟（纯本地正则 + 一次库查询）、不改提示词字节、
   用户侧零可见变化。

## 插件自己能解决的部分（不交给模型）

| 问题 | 现状 |
|---|---|
| 同一事实前后矛盾 | `facts.decide_fact` 自动 supersede（已有） |
| 同一条消息重复投递 | `/event` 幂等（本轮新修） |
| 时间表述换算 | `timeparse` 本地解析（已有） |
| 上下文里塞太多 | 预算裁剪 + 自适应角色卡（已有） |
| 预筛漏抽 | heuristic 模式（已有；实测不是瓶颈） |

## 顺带发现的一个 CI 隐患

`tests/test_m25_1_queue.py::test_queue_reaches_prompt` **在夜间必挂**：
`Curiosity.prepare()` 受 `quiet_hours` 限制，23 点后直接返回 None，测试却断言非 None。
这不是产品 bug，是**时间相关的 flaky 测试**——CI 在夜里跑就是红的。
修法：测试里显式关闭 quiet_hours，或传入固定的白天 `now`。
本轮先记录，未改（避免动到别人的测试语义）。
