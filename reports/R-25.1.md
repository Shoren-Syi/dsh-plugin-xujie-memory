# R-25.1 · 队列生成

**日期** 2026-11-06　**花费** ¥0

## 做了什么

1. **迁移 015**：新建 `curiosity` 表。没复用 `doubts`——`doubts` 是"这句话我没听懂"，
   `curiosity` 是"我想问你点什么"。两者的额度、静默、冷遇规则完全不同
   （疑问挂在回复里，每轮最多一条；好奇在对话之外找机会开口，每天最多三条且避开深夜）。
   塞进一张表，每个查询都得先写 `WHERE source='x'`，迟早有人漏。
2. **`Store.curiosity_gaps()`**：四条 SQL 一次查完，零 token。
3. **`hippo/core/curiosity.py`**：`Gap` / `collect_gaps` / `build_queue`，
   优先级 = `impact × urgency × novelty`。
4. **`hippo curiosity --list`**：走的是和线上**同一个** `build_queue`。

## 四类缺口

| 类 | SQL 判据 | 为什么它算缺口 |
|---|---|---|
| `doubt` | `expires <= now AND resolved = 0` | 问过没答案。过期之后 `pick_doubt` 明确拒绝再注入（`should_ask` 第 5 条），不换通道就等于永远不问 |
| `entity` | pinned 事件里出现、`card_traits` 一条 active 都没有 | 你钉住的事里提了三次的人，角色卡上只有名字——这是"记了但没懂" |
| `trait` | `valid_to IS NULL AND confidence < 0.5 AND 30 天没更新` | 半信半疑的推断。问一句就能扶正，不问就一直拿它当事实用 |
| `fact` | `valid_to` 在最近 30 天内、且同 key 没有新的 active 值 | 老地址、老公司。**"空着"比"记错"更危险**：下游会拿旧值当现值用 |

第四条特意排除了"有新值"的情况：`set_fact` 换值时会把旧的 `valid_to` 写上，
如果新值已经在了，这个缺口根本不存在——问了就是"你搬家了吗"式的装傻。

## 打分

```
priority = impact × urgency × novelty
```

- **impact**：疑问用自己的 `impact`；失效事实 0.70（会被当现值用）；
  只有名字的人 0.75（钉住过，说明重要）；半信半疑的特征 `0.45 + (0.5 - confidence)`——
  越不确定越值得问，0.2 的推断算 0.75。
- **urgency**：`0.15 + 已搁置时间 / 尺度`，封顶 1。尺度按类分：
  疑问 7 天、事实 14 天、人物 30 天、特征 60 天。起步给 0.15 而不是 0——
  刚冒头的缺口也该排得上队；封顶 1 而不是线性外推——
  搁了一年的老账不该压过十件新事。
- **novelty**：`0.5^问过次数`，地板 0.25。地板是必须的：
  归零会让"问过但没答上"的缺口永远沉底，而那正是最该再问一次的。

疑问的 novelty 额外加上 `asked_count`——它在对话里可能已经被问过两遍，
那条通道的失败经验必须算进来。

## 去重

两道：
1. `gap_ref`（`doubt:12`）三天内问过 → 跳过。
2. 问题文本的 trigram 相似度 > 0.8 → 跳过。只按 ref 去重挡不住"换个说法再问一遍"。

## 两个措辞上的决定

- **`fact` 的 key 要翻译成人话**。`facts.key` 存的是英文正名（`city`），
  直接念出来就是"你之前说 city 是杭州"——一张嘴就暴露了它是从库里查的。
  用 `fact_keys().get(key).cn` 换成"居住城市"。
- **问题一律以问号收尾**，且长度受控（`_clip` 18/12 字）。好奇问的是一句话，
  不是一段话——长了就变成审讯。

## 一个被测试抓出来的坑

`answer_overlap("第 0 件事后来怎么样了？", 同样的句子)` 返回 **0.0**。
原因是实义块切分把"怎么"当虚词劈掉，留下 `第 0 件事后来样`，
它在原句里不是连续子串，于是匹配失败。教训：疑问块匹配假设
"回答里会出现连续的实义词"，对复读式回答不成立——这条在 M25.2 里
用"三分钟内开口"的时间证据补上了。
