# R-12.3 阈值标定

> 里程碑：M12.3
> 日期：2026-11-05
> 产出：`tools/tune_trigger.py`、`tests/fixtures/dialog_100.jsonl`
> 结论：**未达标，但结论清楚**。触发率 **45%**（要求 20~35%），漏触发 **13%**
> （要求 <10%）。五档阈值给出完全相同的数——**这不是调参能解决的问题**，
> 是判据类型的天花板。原因和替代方案见第四、五节。

---

## 一、标定集

99 对真实口吻的连续对话（`dialog_100.jsonl`），人工标"这一轮有没有换话题"：

| 类别 | 条数 | 说明 |
|---|---|---|
| 延续 | 68 | 同一话题的追问、补充、呼应 |
| 切换 | 31 | 跳到另一个话题（"对了""算了""明天几点开会"） |

切换率 31%，落在手册预期的 20~35% 区间内——说明这份对话的**话题节奏**是对的。
变的是判据，不是数据。

标注方式：先按话题组（居住/工作/饮食/宠物/人物/日程）自动标，再人工复核。
复核改过 1 条（"早上八点，你提醒我" → "明天几点开会" 是延续不是切换）。

## 二、五档扫描

```
$ python3 -m tools.tune_trigger
对话 99 轮，人工标切换 31 轮（31%）  节流间隔 0 轮
相似度分布：J=0:47  0~.15:0  .15~.25:0  .25~.35:0  .35~.55:36  >.55:16

   th     触发率     漏触发     误触发      触发轮数
 0.10     45%     13%     26%        45
 0.15     45%     13%     26%        45
 0.20     45%     13%     26%        45
 0.25     45%     13%     26%        45
 0.30     45%     13%     26%        45
 0.35     45%     13%     26%        45

没有一档同时满足「漏触发 <10%」——说明判据本身不够，别调阈值。
```

**六档完全一样。** 因为相似度只有三个值：0（判切换）、0.5/0.8/1.0（判延续）、
0.9（共现）。0.10~0.35 之间没有任何样本，阈值在这个区间里随便取都一样。

手册预期"0.25 时触发率 27%、漏 8%"，实际是 45%/13%。差距不在阈值，在分布形状。

## 三、为什么 45% 压不下去

45 条触发 = 27 条真切换 + 18 条误触发。

那 18 条误触发长这样：

| 上一轮 | 这一轮 | 判据看到 | 实际 |
|---|---|---|---|
| 我昨天搬家了 | 房租涨了多少 | 无共同词 | 同一件事 |
| 房租涨了两千 | 那边通勤怎么样 | 无共同词 | 同一件事 |
| 养了只年糕 | 什么品种 | 省略追问（0.8） | 延续 |
| 在哪个医院 | 挂号难吗 | 无共同词 | 同一件事 |

**它们的共同点：同一话题的新侧面，词面上一个交集都没有。**

这是对话的本质——每一句都在给**新信息**。用"词重合"判断话题延续，
等于要求用户重复自己说过的话。

四种判据都试过了：

| 判据 | 结果 |
|---|---|
| Jaccard（手册） | J 恒为 0，五档无差异 |
| 覆盖率 | 45%，误 26% |
| 覆盖率 + 指代/省略 | 45%，误 26% |
| 覆盖率 + 指代/省略 + 共现扩展 | 45%，误 26%（修掉的 3 条被新增的 3 条抵掉） |

最后一行值得说：共现扩展修好了"我搬家了 → 房租涨了多少"（同一条事件），
但它同时把一些"跳回旧话题"也判成了延续——**净收益为零**。
留着它，因为它在事件更多、话题更集中的真实库上会更有用（44 条事件的
共现图太稀疏）。

## 四、成本到底超没超

**没有。** 因为"检索"和"替换 pack"是两件事：

| | 每轮成本 | 45% 触发时 |
|---|---|---|
| 判据 | 0.05ms | 0.05ms |
| L1+L2（触发时） | 0.4~3ms | 平均 1.5ms |
| **token** | 0（检索不注入） | **0** |

真正花 token 的是"把新记忆块写进 prompt"。那由 M13 决定，而不是 M12：

- 每轮都替换 → 45% × 600 = 270 token/轮
- 结果级复用（新 pack 和旧 pack 重合度高就不换）→ 实际替换率会低得多，且**缓存命中**

所以 M12 超标 10 个点，不直接等于成本超标。M13.3 会用真机缓存命中率判定
"成本模型成不成立"，那才是最终裁决（手册的 P2 Gate 写的就是这条）。

## 五、三条改进方向（留给后续里程碑）

1. **M15 夜间巩固**：把共现图做成正式的话题簇（现在 44 条事件太稀疏）。
   有了簇，"房租"和"通勤"会被归到"搬家"这个簇里，覆盖率立刻可用。
2. **结果级复用**（M13）：不问"要不要检索"，问"新结果和旧 pack 差多少"。
   这是唯一不看语义、只看事实的判据——因为比较的是**检索结果**，不是猜测。
3. **embedding**：一个 20MB 的本地小模型能把这层做到 85%+。但违反"少依赖"，
   且每次要 5~10ms。除非前两条都失败，否则不做。

## 六、这一节的方法论

**没有为了让表好看去改 fixture。**

标定集是先写的（99 轮），判据是先设计的（覆盖率 + 指代），跑出来 45%/13%
就报 45%/13%。中途发现"早上八点你提醒我 → 明天几点开会"标错了，改了那一条
标注——因为那是标注错误，不是判据错误。这两件事必须分清：
**改标注是修数据，改判据是拟合。**

```
$ python3 -m tools.tune_trigger --interval 3
   th     触发率     漏触发     误触发
 0.25     18%     74%     15%      ← 节流 3 轮，不可用
```
