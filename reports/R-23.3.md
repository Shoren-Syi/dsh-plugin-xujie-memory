# R-23.3 · 懊悔记忆

**日期** 2026-11-06　**花费** ¥0

## 做了什么

1. **`make_regret()`**：`rpe ≤ -0.5` 时写 `kind=regret`、`w0=0.85`、
   `source=ai`、`tier=2`，摘要走手册模板：

   > 我{动作}，{用户的反应}，要求下次{该怎么做}。

2. **keywords** = 动作类型标配词（擅自 / 改文件 / 未询问）+ 动作与反馈里的
   实义块（≤6 个）。标配词保召回，实义块说明"到底介意什么"。
3. **定向检索 `recall()`**：`detect_kind(upcoming_action)` → 按 typed 关键词
   查 `kind=regret`，按 weight 倒序取 1 条。
4. **pack 两处改动**：
   - `_drop_regret()`：D 段剔除 regret（第 4 条"不进常规 pack"）
   - `_dynamic(upcoming_action=...)`：真要动手时注入 `[教训]` 一行，
     排在存疑/计划/情绪之前
5. **`hippo stats --ledger`** 列出最近 5 条懊悔摘要。

## 关键决定

- **拦在装配层，不拦在检索层**。`_EXCLUDE_KINDS` 保持只有 idle/raw/giveup。
  regret 是正经记忆（w0=0.85 能活 180 天），该被 `hippo recall` 查到、
  该在评测里被数到。要拦的是"自动注入"。
  测试同时钉两件事：`l2_search` 能查到它 **且** `pack` 里 0 出现——
  否则"不进 pack"可以靠"根本查不到"作弊。
- **教训排 E 段第一位**。E 段裁剪切的是尾部，顺序即优先级。
  "别重犯上次那个错"比"我还有个疑问没问"重要。
- **tier 给 2 不给 1**。手册只规定 w0=0.85。写死 hot 会让一条不相关的
  懊悔赖在 hot 池里挤占位置；让权重自己算，它会自然升上去。
- **摘要不带数字**。RPE、predicted 一律不上桌——日记本上的数字给 AI 看，
  它会开始解释这些数字（"我 RPE -0.8，说明我很失败"）。那不是人格，是账本。
- **"我"只在动作不以第一人称开头时补**，否则出现"我我改了配置"。

## 验收对照

| # | 要求 | 结果 |
|---|---|---|
| 1 | 正确触发 | rpe=-1.85 → 生成；rpe=-0.1 → 不生成 |
| 2 | 高权重 | `w0=0.85`、`weight=0.85`、`kind=regret`、`source=ai` |
| 3 | 定向检索能命中 | "我想改配置" 命中；"我要发消息" 0 命中（不跨类） |
| 4 | 不进常规 pack | 常规 pack 0 出现；带 `upcoming_action` 时出现且含"下次先问我" |
