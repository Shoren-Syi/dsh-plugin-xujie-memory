## 3. raw 锚定：这一层最重要的东西

模型最大的毛病不是"抽少了"，是**顺手润色**。实测会出现的六种改写：

| 模型给的 raw | 原文 | anchor_raw |
|---|---|---|
| `我昨天下午搬家了` | 同 | ✅ 原样 |
| `从朝阳搬到海淀` | 长句中的片段 | ✅ 子串 |
| `明天8点叫我` | `明天８点叫我起床` | ✅ 归一化后映射回原文 |
| `我昨天去了杭州` | `我 昨天 去了 杭州` | ✅ 去空白后映射 |
| `我无法忍受了，这破公司天天加班` | `我实在受不了了…` | ❌ 拒绝 |
| `我昨天下午搬家了从朝阳搬到海淀` | 两句 | ❌ 拒绝 |

只做两级匹配（原样子串 / 归一化后子串），**不做相似度**。

理由：一旦允许"差不多就算"，润色过的句子就会入库，而"原文是唯一真相源"这条原则就废了——你再也无法区分哪句是用户说的、哪句是模型替用户说的。三个月后 AI 会笃定地引用一句用户从未说过的话，而查不出是哪一步编的。

**能锚定才入库，锚不上就丢弃。丢的是内容，不是真相。**

## 4. 三处"看起来多余"的防御

### 4.1 `render_prompt` 用 `replace` 不用 `format`

`str.format` 遇到对话里的 `{` 就崩：

```python
render_prompt('user: 我写了个 {x} 的模板')
# format 版：KeyError: 'x'
# replace 版：正常，{x} 原样保留
```

这种崩溃发生在生产环境，表现是"抽取随机失败"——用户说一句带花括号的话就触发，**最难查的那类故障**。有一条测试钉住它（`test_render_survives_braces`）。

### 4.2 `arousal` 的十分制容错

模型经常把 0~1 的强度写成 0~10（"这件事很强烈，8 分"）。`_clamp01` 的处理：

```
v <= 1   → 原样
1 < v <= 10 → 除以 10
v > 10   → 夹到 1.0
```

不这么做的话，DB 的 `CHECK (arousal BETWEEN 0 AND 1)` 会把整条事件打回，而报错信息是 `IntegrityError`——你会以为是"库有问题"。

### 4.3 关键词清洗放在 schema 层，不是 M6

手册把关键词质量放在 M6.1。我在 schema 层先做最小集（去泛词、去重、限 3~6），因为**验收项里就有"schema 合法"**，而"keywords: ['事情','问题']"的 schema 是合法的、质量是零的。

`_EMPTY_WORDS` 里 28 个词，都是"命中一切等于什么都没命中"的。实测端到端时，模型给的 `["对话"]` 被清成 `[]`，然后 persist 退回用实体名兜底——这个链路是通的（见 R-5-Gate）。

## 5. 关于"schema 合法率 ≥98%"这条验收

手册要求"100 次抽样"。**我做不到**，因为没有真实 API key，无法调 100 次。

我做的替代：
- 构造 10 条**真实形态**的模型输出（围栏 / 开场白 / null / 缺字段 / 十分制 / 多余字段 / 字符串下标 / 嵌套引号 / 截断）
- 全部通过

这能证明"解析器足够宽容"，**不能**证明"真实模型的 100 次里有 99 次合法"。

两者差别很大：前者是代码质量，后者是模型遵从度。后者只能真机验。

**已登记为未验证项 U-1，见 R-5-Gate。**

## 6. prompt 的结构：为缓存而排

```
字符位置    内容              变不变
0    ~166   角色设定           固定
166  ~1320  10 条抽取规则      固定   ← 前缀 2774 字符
1320 ~1526   输入格式说明       固定
1526 ~2774   输出格式 + JSON 示例  固定
2774 ~       已认识的人          每窗口可变
~           对话原文            每窗口可变
```

固定前缀 2774 字符 ≈ 1700~2800 token，超过 DeepSeek 上下文缓存的 1024 token 门槛。

**为什么把"已认识的人"从第一节挪到第四节**：第一版它在最前面，于是前缀只有 166 字符，永远不命中缓存。挪到后面之后，89% 的输入走 cache hit（0.5 元/M 而不是 2 元/M）。

这不是微调，是 40% 的成本差。见 R-5.2 §4 的账。

## 7. 一条拒绝

手册 M5.1 的 schema 里 `traits[].evidence` 用 `[0]` 表示"这条特征由第 0 条 event 支撑"。我保留了这个设计，但加了一条手册没写的规则：

> `status: inferred` 且 `evidence` 为空的 trait，**直接丢弃**，不入库。

理由：没有证据的推断就是模型的主观印象。它在 prompt 里看起来无害（"用户可能比较内向"），但 M7 渲染角色卡时会变成一句陈述句，M20 情绪机制会拿它当事实用。三个月后用户问"你凭什么觉得我内向"，你答不上来——因为证据链在入库那一刻就断了。

宁可不记。
