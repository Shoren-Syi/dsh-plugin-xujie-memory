## 3. 一个必须记下来的测试陷阱

**httpx 的 `ASGITransport` 会把所有响应块 `b"".join()` 成一个。**

```python
class ASGIResponseStream(AsyncByteStream):
    async def __aiter__(self):
        yield b"".join(self._body)      # ← 全合并
```

后果：任何用 `ASGITransport` 写的"流式测试"都**必然通过**，哪怕你的代码是先 `read()` 全量再一次性 yield。这是最容易自欺欺人的一种绿。

处理方式（两条都用上了）：
1. `test_relay_yields_per_line`：直接对生成器计数，**结构性**证明没有缓冲；
2. `test_stream_is_incremental_over_tcp`：起真 uvicorn 绑随机端口，过一遍真 TCP。

## 4. 遗留问题

| # | 问题 | 影响 | 处理 |
|---|---|---|---|
| 1 | 客户端断开的检测依赖 Starlette 的 `listen_for_disconnect` 取消协程，而非显式 `is_disconnected()` | 极少数情况下上游连接会多存活到下一个 chunk 才关 | `finally` 里 `upstream.aclose()` 已覆盖；M28 压测时再核 |
| 2 | 未做 chunk 级背压 | 客户端极慢时内存里会积压 | 角色对话速率下不会触发 |
| 3 | `stream_options` 注入会改变请求体字节 | 不影响前缀缓存（它不是 prompt 的一部分），但会让 cassette key 之外的报文不完全一致 | 已确认无影响 |

**通过**。流式是真的流式，不是"分块返回"。
