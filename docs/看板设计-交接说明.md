## 1. 项目一句话

`hippocampus-deepseek` 0.2.0：给 DeepSeek / DSH 加「记得住事」的本地记忆插件。
两种形态：

- **DSH 插件**（`dsh plugin add link:<dir>`）：自动拉起本地 Python 内核、订阅会话事件、注入记忆。
- **OpenAI 兼容代理**（`hippo serve`）：任何客户端改 `base_url` 即用。

记忆库：本地 SQLite（`~/.hippo/mem.db`）。不训练、不上传。

## 2. 看板目标（你接的活）

做一个「记忆看板」：

1. **DSH 侧栏面板**（首选）：DSH Web 左侧栏出现「记忆」入口，点开是看板页。
2. **独立页面兜底**：内核自带 `GET /board` 页面，浏览器直接打开也能看。

两种方案都接受；侧栏是加分项，独立页面必须能跑。

## 4. 数据必须真实（红线）

看板展示的每一条都必须来自真实 SQLite，**不许静态演示数据、不许造假**。

数据接口（内核实现在 `hippo/dsh_kernel.py` + `hippo/core/store.py`）：

```
GET  http://127.0.0.1:<port>/board         看板页面（HTML）
GET  http://127.0.0.1:<port>/board/data    真实数据 JSON
GET  http://127.0.0.1:<port>/health        就绪探针
POST http://127.0.0.1:<port>/event         写一轮 {session, role, text}
POST http://127.0.0.1:<port>/assemble      取本轮记忆文本 {session, text}
```

`/board/data` 当前返回（`store.board_snapshot()`）：

```json
{
  "ok": true,
  "db": "C:\\...\\mem.db",
  "counts": {"events": 29, "facts": 4, "entities": 9, "turns": 120, "doubts": 4, "extract_runs": 38, ...},
  "tiers": {"hot": 1, "warm": 27, "cold": 1},
  "events": [{"id":1,"session":"...","event_time":1793...,"summary":"...","raw_preview":"...","keywords":"...","tier":2,"weight":0.57,"pinned":0}],
  "facts":  [{"id":1,"key":"city","value":"杭州","session":"...","entity_id":3,"confidence":0.9}],
  "entities":[{"id":3,"canonical":"张三","type":"person","confidence":0.8,"aliases":"..."}],
  "turns":  [{"session":"...","idx":12,"role":"user","content":"...","ts":1793...}],
  "doubts": [{"id":1,"session":"...","question":"...","impact":0.6,"cost":0.2}],
  "nodes": [...], "edges": [...]
}
```

SQLite 表（真实结构）：

- `events(id, session, event_time, summary, raw, keywords, tier, weight, pinned, entities, ...)`
  tier: 1=hot / 2=warm / 3=cold；weight 0..1
- `facts(id, session, entity_id, key, value, valid_to, confidence, ...)`（valid_to 为空 = 当前有效）
- `entities(id, session, canonical, aliases, type, confidence, ...)`
- `card_traits(id, entity_id, trait, evidence, confidence, ...)`
- `turns(session, idx, role, content, ts, ...)`
- `doubts(id, session, question, impact, cost, resolved, ...)`

**建议的展示**（按海马体现有结构，不是 xujie 的三层）：

| Tab | 数据 | 视觉建议 |
|---|---|---|
| 事件 | events | 卡片带 tier 色条（hot 青 / warm 琥珀 / cold 灰）、摘要、关键词、时间 |
| 事实 | facts | key=value、置信度、会话 |
| 人物 | entities | canonical、type、置信度、别名 |
| 三维场 | events（按 tier 分层）+ entities（大节点） | 边：同会话相邻事件；点击节点→详情 |

## 6. 技术选型建议

**方案 A（最快，推荐先做）：独立页面**
- 重写 `hippo/data/board.html`（自包含 HTML+CSS+JS，无构建）。
- 直接读 `/board/data`，暗色、三维场、列表、搜索、详情。
- 验证：`python -m hippo.dsh_kernel --db <库> --port 8794` → 打开 `http://127.0.0.1:8794/board`。

**方案 B（加分）：DSH 侧栏面板**
- 参照 xujie 的 client 半：`export const name`、`export const inject = ['slots']`、`ctx.slots.inject('sidebar.panellist', ...)` + `main`。
- 需要 React + 打包（xujie 用 esbuild 打成 `lib/client.js`，`window.__ModuleLoader__.load(...)` 格式）。
- 插件 manifest 的 `dsh.client` + `exports["./client"]` 已在 `package.json` 声明。
- 数据可直接 fetch 内核端口（内核已开 CORS）。

## 7. 验收标准

1. 打开页面/面板，数据与真实库一致（`/board/data` 的 counts、列表条数）。
2. 三维场：soma + 三层纤维 + 发光粒子 + 脉冲 + 自转，**观感接近 xujie 0.8**（暗色、精致、不土）。
3. 事件/事实/人物三个视图 + 搜索过滤 + 点击详情。
4. 空库时有明确空状态（“还没有记忆，在 DSH 里聊天几轮”）。
5. 无控制台报错；1280×800 和 1920×1080 都不溢出。
6. 独立页面必须能在 `file://` 与 `http://127.0.0.1:8794/board` 下都工作。
